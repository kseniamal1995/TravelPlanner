# UX-анализ и план упрощения (prototype v9)

_Дата: 2026-06-09. Основа: `paris-planner.html` + `project-docs.md`._

## Вердикт

Главная проблема прототипа — **плотность, а не структура**. Экраны и навигация в целом правильные, но карточка места показывает всё и сразу (до 11 элементов), управление размазано по дублирующим точкам входа, а ключевые действия спрятаны за двухшаговыми скрытыми меню. Симптом: в UI уже появились тексты-инструкции («Перетащи нужное в день кнопкой „Изменить → перенести“») — если интерфейсу нужна инструкция, он переусложнён.

---

## 1. Что переусложнено

### 1.1 Карточка места — стена текста (критично)
В развёрнутом виде карточка содержит: название, рейтинг, бейдж «Забронировано», описание, до двух предупреждений (⏰ и ⚠️), чип цены, чекбокс «куплено», ссылку на сайт билетов, lead-текст, ссылку Google Maps, кнопку «Изменить». День 5 — 8 таких карточек подряд: экран превращается в простыню, маршрут «не читается» как маршрут.

При этом в требованиях продукта прямо написано «**описание места по тапу**» — то есть карточка и задумывалась компактной.

**Решение:** свёрнутая карточка по умолчанию — название + рейтинг + одна статусная строка (`🎟 €22 · слот пт 9:30` / `⚠️ закрыт вт`). Тап раскрывает описание, предупреждения, ссылки, заметку.

### 1.2 Скрытый редактор в каждой карточке
«Изменить» открывает: textarea заметки + кнопки ↑↓ + select переноса + удаление. Проблемы:
- сортировка по одному шагу на тап (карточка «прыгает» после каждого ре-рендера);
- select «перенести» смешивает дни (даты) и категории идей в одном списке;
- редактор повторяется в каждой карточке — тяжёлый DOM и визуальный шум.

**Решение:** действия с местом — через bottom sheet (перенести / удалить / заметка), позже drag-handle для сортировки. В Telegram это привычный паттерн.

### 1.3 Управление днями — в трёх местах
1. «+ день» в табах; 2. «🗑 Удалить этот день» внизу ленты каждого дня; 3. степпер «Дней» в настройках (при уменьшении молча отправляет места в «На потом»).

**Решение:** одна точка управления. «+ день» оставить в табах, удаление — лонг-тап/меню на табе дня или в настройках. Постоянно видимую деструктивную кнопку убрать. Степпер из настроек убрать совсем (дублирует «+ день»).

### 1.4 Насыщенность дня закодирована трижды
Цвет фона таба + цветная обводка активного таба + чип «🟢 лёгкий день» + модалка по «?». При этом активный таб обозначен слабо (inset-обводка 1px конфликтует с цветным фоном) — главный state «какой день открыт» виден хуже, чем второстепенный «какая нагрузка».

**Решение:** табы нейтральные, нагрузка — маленькая цветная точка под датой; активный таб — контрастная заливка. Чип нагрузки оставить один, модалку «?» заменить строкой пояснения в самом чипе/под ним.

### 1.5 Два параллельных статуса билета
`booked` (бейдж «✅ Забронировано») и `bought` (чекбокс «куплено») — пользователь не различит. Плюс ticket-блок из 4 элементов (чип цены, чекбокс, ссылка, lead-текст).

**Решение:** один статус: `нужен билет → куплен/забронирован (+ дата/время)`. Одна строка: цена + дедлайн брони + действие.

### 1.6 «Идеи» — скрытая вторая иерархия
Отдельный экран за кнопкой 💡 справа сверху, внутри три под-вкладки. «На потом» одновременно — категория идей и свалка мест из удалённых дней. Перенос идеи в день — двухшаговый скрытый флоу, потребовавший текст-инструкцию.

**Решение:** один список «Копилка» с чипами-фильтрами (🛍 / 🍽 / 📌) вместо под-вкладок; перенос в день — основное действие на карточке идеи («+ в день N»), а не пункт селекта.

### 1.7 Навигация — мелкие кнопки в недосягаемой зоне
⚙ 💡 🔔 — три иконки в правом верхнем углу: худшая зона для большого пальца, а в Telegram Mini App верх ещё и конкурирует с шапкой Telegram (кнопка закрытия/меню).

**Решение:** нижняя навигация внутри поездки (План / Идеи / Напоминания) или вынос в Telegram MainButton/BackButton при переходе на TMA. «+ Добавить место» — кандидат №1 на MainButton.

### 1.8 Напоминания-простыни
Текст напоминания про метро — ~250 знаков в карточке. Два входа в раздел (с главной и из поездки) с разным scope; переключатель «Эта поездка/Все» дублирует навигацию.

**Решение:** заголовок (1 строка) + детали по тапу. Scope определять контекстом входа без переключателя (из поездки — поездка, с главной — все, с группировкой по городам).

### 1.9 Мелкое, но влияет на ощущение качества
- Поля времени — свободный текст (`10:35`) → `type="time"` (иначе позже сломается парсинг).
- Touch-targets меньше 44px: «?» — 18px, чекбоксы 16–18px, «Изменить», ↑↓.
- Нативный `confirm()` на удаление → заменить на toast с «Отменить» (undo вместо вопроса).
- Подзаголовки дней (`daySub`) захардкожены под seed — новые дни без описания.
- Текст в модалке новой поездки «скинь места/скрины — наполню» — из чат-воркфлоу; в standalone-аппе это тупик. Пустой день должен вести к действию («+ Добавить место»).

### 1.10 Данные есть — в UI не показаны (упущенная ценность)
- `pri` (must/want/opt) нигде не визуализирован — а «must-see в первый день» это ядро продукта.
- `rec` (рекомендация аппа) не отличим от мест пользователя — а «подсказывать прикольные места» это ключевая фича. Рекомендации должны быть видимы (бейдж «✨ совет») и легко отклоняемы.

### 1.11 Найденный баг
Открыть «Напоминания» с главной → переключить на «Эта поездка» → краш рендера: `city()` возвращает `undefined` при `activeCity === null` (`remHtml` → `cities=[city()]`).

## 2. Что НЕ трогать (уже хорошо)

- «🏨 Старт от отеля» строкой + перегоны между точками — читается отлично.
- «🛬 Прибытие и заселение» свёрнутым блоком — правильный паттерн (его и распространить на карточки).
- У забронированного места скрыта цена — верное сокращение шума.
- Авто-даты дней, миграция данных с сохранением галочек, empty states.
- Сама идея индикатора нагрузки — оставить, упростить только подачу.

## 4. UI-редизайн по референсам (итерация 3)

_Статус: ✅ реализовано 2026-06-09 (schema v11). Все пункты 4.1–4.6 внесены; иконки — собственный inline-словарь в стиле Lucide (24 шт.); шрифты Source Serif 4 + Onest; флоу «+ день» с темами и выбором мест из копилки работает, тема дня становится подзаголовком._

_Референсы: mindtrip.ai (цвета, формы), Rhyme/ex-Roamy (чистота, плотность), storytelling.noomoagency.com (характер микроанимаций — сдержанно и целенаправленно)._

### Направление
«Тёплый editorial-минимализм»: бумажный светлый фон, чернильный текст, хвойный зелёный акцент, чёрные CTA-пилюли, серифные заголовки + современный гротеск для UI, большие радиусы, мягкий выверенный моушн. Сиреневый акцент уходит.

### 4.1 Дизайн-токены
- Фон `#F6F3EC` (тёплая бумага), карточки `#FFFFFF`, линия `#EAE6DC`.
- Текст: ink `#20241F`, soft `#75796F`.
- Акцент: хвойный `#35563B`; мягкая подложка `#E4EDE2`. CTA — чернильные пилюли (ink), как у mindtrip.
- Семантика: «куплено/брони» — зелёный `#3E7A47/#E4EDE2`; предупреждения — янтарь `#9A6A12/#F3E8D2`; опасность — глина `#B5472F/#F6E3DC`. Точки нагрузки: `#4C8A52 / #C98A1B / #C24B33`.
- Радиусы: карточки 20, табы/кнопки-пилюли 999, шиты 26 сверху. Тени мягкие двойные + 1px тёплая линия.

### 4.2 Типографика (обязательно кириллица)
- Display: **Source Serif 4** (700–800) — заголовки экранов, названия поездок, даты в табах. Современный сериф в духе mindtrip.
- UI/текст: **Onest** (400–800) — всё остальное. Альтернатива: Golos Text.
- Nunito уходит. Размерная шкала: H1 32, H2 20, карточка 16.5, мета 13, чипы 12.5.

### 4.3 Иконки — единая SVG-библиотека (Lucide-стиль)
Inline-словарь `ICONS` (stroke 2, currentColor, 18–20px, одна оптическая сетка). Замены: ⚙→sliders, 🔔→bell, 💡→lightbulb, 📍→map-pin, 🗺→route, 🎟→ticket, ⏰→clock, ⚠️→alert-triangle, ✅→check-circle, 📝→sticky-note, 🚶→footprints, 🚇→train, 🚌→bus, 🚕→car, 🏨→bed, 🛬→plane-landing, ✈️→plane, 🌙→moon, 🛍→shopping-bag, 🍽→utensils, 📌→bookmark, ›→chevron. Контентные эмодзи в названиях мест (🥐☕🍜⭐) остаются — это характер, не интерфейс.

### 4.4 Микроанимации (инвентарь, всё CSS, + prefers-reduced-motion)
1. Смена дня/экрана — staggered reveal карточек (fade + 10px вверх, ~28мс шаг, cap 8).
2. Шиты — выезд снизу с фейдом подложки (сейчас появляются мгновенно).
3. Нажатие — scale(.97) на всех кнопках/карточках, 120мс.
4. Раскрытие карточки — есть; добавить фейд содержимого.
5. «Билет куплен» — чек-поп с овершутом (260мс).
6. Активный таб — короткий поп + пинг точки нагрузки.
7. Нижняя навигация — подсветка-пилюля и сдвиг иконки на 2px.
8. Тост — пружинный овершут (уточнить кривую).
9. Новая карточка после добавления — тёплая вспышка фона.

### 4.5 Функциональное в этой итерации
- Количество дней — обратно в настройки (степпер), уменьшение переносит места в «На потом» с тостом-undo; лонг-тап на табе остаётся шорткатом.
- Новый флоу «+ день»: шит «Новый день · 7 июля»: (1) чипы «Что хочешь делать?» (достопримечательности / музеи / еда / шопинг / прогулка / фото) → тема дня, станет подзаголовком и позже входом для LLM-движка; (2) чек-лист оставшихся мест из «На потом»/Идей — отметить и забрать в день; (3) «Создать день».

### 4.6 Порядок работ
1. Токены + шрифты → 2. Словарь иконок + сквозная замена → 3. Компоненты (пилюли, табы, навигация, шиты с grabber) → 4. Микроанимации → 5. Дни в настройках + флоу нового дня → 6. Смоук-тесты и ручной прогон.

## 5. Итерация 4 — фидбек по редизайну

_Статус: ✅ реализовано 2026-06-09 (schema v12), включая все три идеи: чек-офф «посещено» (флаг `done`, переживает миграции), погода Open-Meteo (видна, когда дата в пределах 16-дневного прогноза), пустые состояния с иконкой-кругом. Фото — Wikipedia REST (31 место в seed с `wiki:`), фолбэк — плитка с иконкой категории; стопка превью на карточке поездки._

### Анализ фидбека
1. **Слишком много жирного** — почти весь текст 600–800. Нужна шкала весов: 400 обычный текст (описания, детали), 500 мета/подписи, 600 чипы и мелкие кнопки, 700 названия мест и CTA, 800 — только display-заголовки. Плюс чуть больше line-height у описаний.
2. **Чёрные кнопки «траурно», цветов мало** — перевести CTA-пилюли (Маршрут, + Добавить, + Новая поездка, Создать день) и активный таб с чёрного на глубокий зелёный (примерно `#2E6B43`); чёрный остаётся только тексту. Янтарь/зелёный/красный семантика остаётся, добавить тепла: терракотовый вторичный акцент для разделителей частей дня и звёзд рейтинга.
3. **Пропал текст индикатора насыщенности** — вернуть словами в строку статистики дня: «Средний день · ~3,9 км · 9 точек», слова окрашены цветом уровня. Кружок остаётся только точкой на табе (без дублирования, как договаривались).
4. **Зелёные линки не видны / грязно** — текстовые ссылки: более чистый яркий зелёный + подчёркивание; ключевые экшены (Google Maps, Билеты, Открыть) — светло-тонированные чипы-пилюли, читаются как кнопки.
5. **Несогласованные флоу создания дня** — убрать «+ день» из табов и лонг-тап совсем. Единый флоу: степпер в настройках добавляет пустые дни; на странице дня всегда видна кнопка «Настроить день» (тот же шит: тема-чипы + взять из копилки + удалить день); пустой день показывает крупный CTA «Собрать день» с тем же шитом. Идея: после увеличения дней в настройках сразу открывать «Собрать день» для первого нового.
6. **6 июля без разделителей** — добавить sect-разделители как у 4 июля: «Вариант A · прогулка» (sun), «Вариант B · кафе с ноутбуком» (coffee), «Отъезд в Орли» (plane + лаконичная заметка тайминга: вылет 18:20 → выезд ~14:30). Иконки sun/coffee/plane добавить в словарь.
7. **Тёмные инпуты выглядят как дисклеймеры** — инпуты и селекты: белый фон, рамка line2, зелёное focus-кольцо. Бежевая подложка остаётся только хинтам.
8. **«Маршрут дня» непонятно куда ведёт** — переименовать в «Маршрут в Google Maps» (+ внешняя стрелка уже есть).

### Фото локаций (проверено: реализуемо без ключей)
Wikipedia REST API (`/page/summary/{title}`) отдаёт превью с CORS `*` — бесплатно, без бэкенда. План:
- В seed добавить `wiki:` (заголовок статьи) для известных мест; ленивый fetch превью с кэшем в памяти.
- Карточка места: превью 56×56 со скруглением слева от названия; без фото — тонированная плитка с иконкой категории (sights/food/shop).
- Карточка поездки на главной: стопка из 3–4 круглых превью мест.
- В проде заменить источник на Google Places Photos (адаптер тот же).

### Мои идеи (опционально, по желанию)
- **Чек-офф «посещено»**: галочка на месте по ходу дня, вычеркнутые места + мини-прогресс в табе дня. Эмоция «день удался» + вход для пересчёта остатка дня движком.
- **Погода на день** (Open-Meteo, бесплатно, без ключа): иконка+градусы у даты дня; влияет на советы (дождь → крытые места).
- **Иллюстрированные пустые состояния** вместо текстовых.

### Порядок работ
1. Веса шрифтов + инпуты + линки → 2. Зелёные CTA и возврат текста индикатора → 3. Единый флоу дней (+ убрать лонг-тап/таб) → 4. Разделители 6 июля → 5. Кнопка «Маршрут в Google Maps» → 6. Фото локаций → 7. Смоук + скриншоты.

### Метрика успеха фазы 1

## 6. Итерация 5 — облегчить интерфейс (фидбек по v13)

_Статус: ✅ реализовано 2026-06-10 (см. docs/07-changelog.md «v15»). Уточнения по второму фидбеку: табы остаются; компактная строка дня; вернуть аффорданс раскрытия карточки; пересмотреть прогресс; ревизия функционала. Третий фидбек: **тему дня в строке дня не показываем** — описания дней («Прогулка и кафе») убрали ещё в v14, тема остаётся скрытыми данными для LLM-движка. Референсы: MyFitnessPal и Lóvi (Mobbin) — светлые, почти монохромные интерфейсы: один акцент, цвет только у семантики, секции — микро-лейблы с волосяными линиями, карточки без рамок на тонированном фоне, много воздуха._

### Анализ фидбека

1. **Верх страницы дня перегружен.** До первой карточки — 6 блоков: шапка (назад + заголовок + саб + шестерёнка), табы, toprow (CTA «Маршрут» + кнопка «Настроить день» + погода · нагрузка · км · точки), прогресс-бар, инфострока прибытия, пилюля «Старт». Две залитые/тонированные кнопки конкурируют за внимание ещё до контента.
2. **Карточка места дублирует информацию.** Строка `.cstatus` (пилюли «билет €22», «забронировано», ⚠) — отдельный ряд цветных плашек; цена билета и статус брони повторяются в раскрывашке (`.tk`, `.booked`). Свёрнутая карточка должна отвечать «что это и нужно ли что-то сделать», детали — внутри.

6. **Вторичная палитра шумит**: терракотовые разделители частей дня (вкладка 6 июля: «Вариант A · прогулка») и рейтинги ★ окрашены, хотя несут второстепенную информацию.

### 6.1 Верх страницы дня → компактная строка дня

**Табы по дням остаются без изменений** — это основная навигация поездки; точка нагрузки на табе — единственная индикация насыщенности (слово «Средний день» из верха уходит, детали — в шите дня).

Вместо toprow (две кнопки + длинная статистика) и прогресс-бара — **одна строка дня** под табами:

```
[Вс 6] [Пн 7] [Вт 8] [Ср 9] …
☀ 26° · 9 мест                          [↗] [···]
```

- **Слева — только факты**: погода + число мест («3 из 9», когда день начат). Тему дня не показываем (описания дней убраны в v14; `day.theme` — скрытый вход для LLM). Километраж и слово нагрузки из строки уходят. Текст `--soft`, 13.5/500.
- **Справа два иконных контрола**: `route` (маршрут в Google Maps, лёгкий чип `acc-bg`) и `···` (открывает daySheet «Настроить день»). Текстовые кнопки «Маршрут» и «Настроить день» уходят. Тап по самой строке тоже открывает daySheet.
- Правило: одна залитая индиго-кнопка на экран («Добавить место» / «Собрать день»).
- **Похожие идеи разгрузки**: psub сократить до «33 места» (число дней видно в табах); пилюлю «Старт от отеля» показывать только при нестандартном старте (`first` задан), дефолтную убрать.

### 6.2 Карточка места: свёрнутая = «что + статус», раскрытая = детали

Свёрнутая (одна мета-строка, без ряда пилюль):

```
[фото 48] Лувр                              (✓)
          Музей · ★ 4.7 · 🎟 ⚠ 📝            ⌄
```

- Слева: категория (текст `--soft`, без подложки) · рейтинг.
- **Статус-маркеры** — только иконки 13px без подложек: 🎟 амбер = нужен билет, зелёная ✓/🎟 = куплено/забронировано, ⚠ ред = предупреждение безопасности, 📝 серый = есть заметка. Цвет только у иконки.
- **Вернуть аффорданс раскрытия**: шеврон в правом нижнем углу карточки (на линии меты, 14px, `--soft2`, поворот 180° при открытии). Галочка «был(а) здесь» остаётся отдельной круглой кнопкой справа сверху — контурный круг → зелёная заливка; с шевроном рядом её больше не примут за «раскрыть».
- Ряд `.cstatus` с пилюлями удаляется; текст «билет €22» / «забронировано · 9:30» живёт только в раскрывашке.
- Раскрытая: время визита, описание, полные предупреждения (амбер/ред плашки остаются — это детальный уровень), билетный блок (цена + дедлайн + ссылка + «куплен?»), заметка, Maps, «Изменить». Каждый факт ровно в одном месте на каждом уровне.

### 6.3 Прогресс дня — минимизировать

Нужна ли индикация вообще: посещённые карточки уже бледнеют, галочка зеленеет — лента сама показывает прогресс. Отдельный бар + лейбл — дублирование (та же болезнь, что у насыщенности в v9: одно состояние закодировано трижды).

- Блок `.dayprog` (бар + «3 / 9 пройдено») **убрать**.
- В строке дня «9 мест» → «3 из 9», когда есть пройденные, — этого достаточно.
- Микро-награда вместо бара: когда день пройден целиком, точка нагрузки на табе становится зелёной галочкой.
- Если на тестах захочется вернуть эмоцию — показывать бар один раз в момент 100% (анимация-вспышка), а не постоянным элементом.

### 6.4 Отступы — единый ритм 4/8/12/16/24

- Между карточками: `.stop` margin 7 → 12; внутри: padding 13/15 → 16.
- Между смысловыми блоками (шапка → табы → строка дня → лента): 16–20.
- Разделители частей дня: `.daypart` margin-top 18 → 28 (секция должна «дышать», как First Steps/Daily Plan в Lóvi).

### 6.5 Бейджи и статусы — облегчить

- Категория: **без подложки** — иконка 12 + текст 12/500 цветом `--soft` (как мета «Caesar Salad and 1 more» в MyFitnessPal). Тоновые классы `badge--warm/food/nature` уходят; badges.css сжимается до одного стиля.
- Если без подложки слишком пусто — запасной вариант: одна нейтральная подложка `--gray-bg` + `--soft` для всех категорий.
- Цветные заливки остаются только семантике: зелёный «готово», амбер «нужен билет», ред «безопасность» — и те светлее (см. 6.6).

### 6.6 Вторичная палитра — приглушить

- Семантические подложки осветлить (ближе к белому): `--amber-bg #F3E8D2 → #F7F0E1`, `--red-bg #F7E4DD → #FAEEEA`, `--green-bg #E4F6EC → #EAF7F0`; текстовые тона не трогаем (контраст).
- Точки нагрузки `--dot-*` приглушить на полтона (пастель) — они индикатор, не алерт.

### 6.7 Современность точечно (по референсам, без редизайна)

- **Карточки без рамок**: убрать `border 1px --line` у `.stop/.tripcard/.flow/.rcard/.inforow`, оставить мягкую тень — фон и так тонированный (главный «осовременивающий» ход обоих референсов).
- **Подача табов** (структура и поведение не меняются): неактивные — прозрачные (без `--pill-bg`), активный — белая пилюля с тенью + индиго-текст, как Day-пилюли у Lóvi.
- **Разделители частей дня**: центрированный микро-лейбл между волосяными линиями (как «Daily Plan» у Lóvi), 11–12px/600, `--soft2`, letter-spacing.
- Модалки: лейблы 800 → 600; заголовки блоков `.arrhdr` оставить 700; контент-текст 400–500.
