# Обзор проекта (актуальное состояние)

Личный планер путешествий — Telegram Mini App. Пользователь задаёт город, даты,
отель, темп и интересы; приложение генерирует через AI пеший маршрут по дням от
отеля и даёт его править руками. Детальные дизайн-доки — `01`–`07`; этот файл —
сводка «что есть сейчас».

## Из чего состоит

**Фронтенд** — Vite + ванильный ESM, без фреймворка. Полная перерисовка экрана на
каждое изменение (`render.js`): мутируем `store.S` → `save()` → `render()`.
- `src/store.js` — состояние + загрузка/сохранение через адаптер хранилища.
- `src/views/` — экраны: `home` (список поездок), `plan` (день по дням), `ideas`
  (места вне плана), `reminders` (напоминания, с табами по поездкам), `nav`
  (нижняя навигация внутри поездки).
- `src/components/stop.js` — карточка места (свёрнута/раскрыта), `arrival.js` —
  блоки прибытия/отъезда, `empty.js` — пустые состояния.
- `src/sheets/` — bottom-sheet формы: `generateTrip` (5-шаговый онбординг новой
  поездки), `addPlace`, `reminder`, `arrival`, `departure`.
- `src/services/` — `api` (REST к бэкенду), `storage` (REST → localStorage →
  память), `telegram` (адаптер Mini App), `photos` (Wikipedia), `weather`
  (Open-Meteo).
- `src/ui/` — `sheet` (общая модалка), `toast` (undo), `tgChrome` (нативный
  BackButton Telegram), `drag` (сортировка).
- `src/styles/` — CSS по слоям (tokens, base, cards, modal, tabs, nav, buttons…).

**Бэкенд** — Express (`server/`), запускается одним процессом, в проде раздаёт
собранный фронт из `dist/`.
- `server/datastore.js` — двойной адаптер: **Postgres** при `DATABASE_URL` (прод
  на Railway), иначе **SQLite** (локально). Асинхронный интерфейс `ds.run/get/all`.
- `server/db.js` — состояние пользователя (один JSON-блоб на user_id).
- `server/cache.js` — кэш справочных данных: `city_profile` (профиль города, слой
  B) и `place` (факты о месте, слой A), общий для всех пользователей.
- `server/services/llm.js` — генерация маршрута и отдельного дня через Claude
  (модель по умолчанию Haiku), с мок-фолбэком без ключа; промпт с правилами
  «человеческого» маршрута + prompt caching на стабильном префиксе.
- `server/routes/` — `state` (GET/PUT состояния), `generate` (POST маршрут и
  `/generate-day`).
- `server/middleware/initData.js` — валидация подписи Telegram + белый список
  `ALLOWED_USER_IDS`.

**Хостинг** — Railway: приложение из GitHub-репозитория + сервис Postgres.
Переменные: `ANTHROPIC_API_KEY`, `LLM_MODEL`, `BOT_TOKEN`, `DATABASE_URL`,
`ALLOWED_USER_IDS`. Бот и Mini App зарегистрированы в BotFather.

## Что работает (функциональность)

- **AI-генерация поездки** по 5-шаговой форме (город/даты → отель/прилёт/заселение
  → темп → интересы → забронированные мероприятия). Возвращает дни с темами,
  места с категориями/рейтингами/билетами/предупреждениями, идеи, напоминания.
  Генерация идёт **вне модалки**: форма закрывается, на главной появляется
  плашка-заглушка с названием города и анимацией; по готовности — готовый маршрут,
  при ошибке — «Повторить».
- **Догенерация дня** — кнопка «+» в табах дней добавляет день и подбирает места
  через AI (не повторяя уже выбранные), со спиннером.
- **Кэш A/B** — факты о местах и профиль города сохраняются в БД и подмешиваются
  в последующие генерации (экономия токенов).
- **План по дням** — карточки мест (свернуты по умолчанию, рейтинг золотой
  звездой, фото), перегоны между точками, нагрузка дня, темы, маршрут дня в Google
  Maps, тонированная плашка прибытия/отъезда (отличается от карточек мест).
- **Билеты** — пилюля «цена + купить» (ссылка) + чекбокс-тоггл «Билет есть», срок
  брони. Бейдж билета только у платных мест.
- **Идеи** — места вне плана (шопинг/еда/на потом); табы появляются по мере
  добавления, пустое состояние с подсказкой.
- **Напоминания** — по поездке и «Все поездки» (табы), точка-индикатор «горящего»
  (просрочено/≤7 дней), иконка в бейдже дедлайна, **свайп-влево для удаления**
  (+ undo), ручное добавление.
- **Погода** — Open-Meteo (без ключа), цветная emoji-иконка + темп, чип в одном
  ряду с кнопкой маршрута (в пределах ~16 дней прогноза).
- **Фото мест** — Wikipedia REST по полю `wiki` (с фолбэком на название места).
- **Telegram** — бренд-тема (не перекрашиваемся под клиент), haptics, нативный
  BackButton, кнопки шита, safe-area, per-user хранилище по подписи initData.
- **Undo** — единичный откат деструктивных действий (тост во всю ширину меню).

## Где проблемы / ограничения

- **Скорость генерации** ~20–40с: длинный запрос может рваться в мобильном
  WebView (см. историю «Load failed»). Нет стриминга/фоновой задачи.
- **Качество маршрута** зависит от модели; на Haiku дешевле, но слабее Sonnet.
  Нет эвалов качества.
- **Google Places не подключён** — рейтинги генерирует LLM (могут быть неточными),
  координаты/ссылки — через поиск Google Maps по названию; живых часов работы нет.
- **Погода не влияет на маршрут** и не обновляется/не предупреждает (см. `09`).
- **UI/UX долг** — несогласованные табы, переполнение текста на узких экранах и
  т.д. (полный список — `08-ui-ux-issues.md`).
- **Миграции состояния**: при смене схемы пользовательские структурные правки
  seed-городов сбрасывались бы — но seed больше не подставляется, поездки
  пользовательские, так что критичность снижена.
- **Один общий ключ/баланс Anthropic** — защищён белым списком + рекомендован
  лимит трат; жёсткого дневного капа на генерации пока нет.
