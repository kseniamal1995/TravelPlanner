## C. Не работает / работает с оговорками

- **Рейтинги мест** — генерирует LLM по памяти, не живые (могут быть неточны).
  Живые — только через Google Places (не подключён).
- **Часы работы / закрытия** — нет живого источника; только то, что LLM положит в
  `warnH`.
- **Скорость генерации** ~20–40с; на длинных поездках длинный запрос может рваться
  в мобильном WebView. Нужен стриминг/фоновая задача.
- **Координаты/ссылки мест** — через поиск Google Maps по названию (`rname`), не
  точный place_id.

## D. Обсуждали, но не реализовали

- **Google Places** — живые рейтинги/часы/фото вместо приближений LLM (платно;
  кэшировать в слой A).
- **Кэш-first генерация** — сперва тянуть факты мест из БД, у AI спрашивать только
  недостающее (сейчас только «подмешивание» known places в промпт).
- **Стриминг / фоновая генерация** — чтобы длинный маршрут не рвался и можно было
  закрыть приложение во время генерации (Фаза 3).
- **Погода → маршрут**: учёт прогноза при генерации (дождь → крытые места);
  предупреждение об ухудшении погоды и reroute с откатом к прежней версии
  (нужна история версий) — подробно в `09-ideas.md`.
- **Пуши по дедлайнам** напоминаний (бот шлёт сообщение) — Фаза 3.
- **Шаринг поездок / совместное редактирование** — Фаза 3.
- **OCR скриншотов** подборок мест на онбординге.
- **Авто-напоминания из `ticket.lead`** — считать дату «бронируй за N недель» и
  заводить напоминание автоматически.
- **Дневной лимит генераций** на пользователя — защита бюджета сверх белого списка.
- **Пре-сид популярных городов** (A+B) — чтобы старт был без затрат на справочные
  данные.
- **Тёмная тема** через `themeParams` Telegram (сейчас бренд жёстко светлый).
- **Эвалы качества маршрута** — сценарии (день прилёта, якорь-событие, день
  отъезда, «чиллее», «добавь еду») до открытия на пользователей.
