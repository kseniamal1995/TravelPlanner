# Продукт

## Видение

Личный планер путешествий: пользователь собирает поездку по городу, приложение раскладывает места по дням в виде **пешего маршрута от отеля** — с учётом часов работы, бронирований, нагрузки дня и предупреждений. Цель — отдавать **готовый «человеческий» маршрут**, который почти не нужно править руками.

Аудитория: путешественники, которые планируют сами и хотят структуру без ручного жонглирования картой.

## Ключевая идея — маршрут «как составил бы человек»

Правила, которые должен соблюдать движок (сейчас зашиты в seed-данные Парижа, в проде — LLM + правила, см. `06-telegram-migration.md`):

- **Кластеризация**: один день = одна пешеходная зона.
- **Якорь дня**: главное по таймслоту/билету (музей, концерт), остальное лёгкое вокруг; два тяжёлых музея подряд — нет.
- **Часы и день недели**: закрытия музеев (пн/вт), воскресенья магазинов, последний вход, таймслоты.
- **Кривая усталости**: лимит точек и километров под выбранный темп ходьбы.
- **Тайминг впечатлений**: рынки утром, закат/подсветка вечером, обед по пути.
- **Маленькие радости**: утренний круассан, перерыв в саду.
- **Контекст прилёта/отъезда**: день прилёта начинается с логистики (аэропорт → отель → багаж), день отъезда — лёгкий, с расчётом времени выезда.
- **Части дня**: если день меняет характер (днём гуляем — вечером концерт), это явно размечено разделителем с инструкцией перехода (вернуться в отель, время на дорогу).
- **Дефолты почти без правок**: пользователь подталкивает («чиллее», «добавь еду»), а не пересобирает.

## Принципы UX (выработаны итерациями, см. ux-plan.md)

1. **Свёрнуто по умолчанию** — карточка места: название + статус-строка; всё остальное по тапу.
2. **Один индикатор — одно место** — насыщенность дня: точка на табе + словесный лейбл в статистике, без дублирования.
3. **Один статус билета** — «нужен билет (цена)» → «куплен/забронирован»; у забронированного цена скрыта.
4. **Undo вместо confirm** — деструктивные действия выполняются сразу, тост с «Отменить» (5 сек, полный откат состояния).
5. **Ни одно действие не требует текстовой инструкции в UI.**
6. **Тач-таргеты ≥ 44px**, основная навигация — снизу (зона большого пальца).
7. **Единый флоу управления днями** — количество в настройках, содержание (тема/места/удаление) — на странице дня.
8. **Эмодзи только в контенте** (названия мест), интерфейс — единая SVG-библиотека иконок.

## Статус MVP

Прототип покрывает: несколько поездок, дни с авто-датами, карточки мест с билетами/предупреждениями/заметками, идеи (шопинг/еда/на потом), напоминания с дедлайнами, индикатор нагрузки, маршрут дня в Google Maps, темы дня, чек-офф «посещено», фото мест (Wikipedia), погода (Open-Meteo), полный undo.

Не реализовано (бэклог — `06-telegram-migration.md`): генерация маршрутов (LLM + Places), онбординг нового пользователя, поиск мест/OCR скриншотов, пуши, шаринг, бейджи must/✨совет, bottom-sheet действий с местом, drag-сортировка.
