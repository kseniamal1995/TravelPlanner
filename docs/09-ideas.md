# Идеи и бэклог

## Погода — что работает, что нет (по запросу)

### 1. Отображение погоды — ✅ работает
- Источник: **Open-Meteo** (бесплатно, без ключа), `src/services/weather.js`.
- Как: по названию города геокодим (Open-Meteo geocoding) → тянем дневной прогноз
  (макс. температура + weather_code) на даты поездки → кэшируем по имени города →
  патчим узлы `[data-wxd]` иконкой + температурой в строке дня (`plan.js`,
  рядом с «Насыщенный день · N мест»).
- Ограничения: горизонт прогноза **~16 дней** — для более дальних дат слот скрыт;
  кэш по **имени города** (одноимённые города не различаются); только дневной
  максимум, без почасовки и осадков в мм.

### 2. Построение маршрута в зависимости от погоды — ❌ не реализовано
- Генерация (`llm.js`) **не получает прогноз** и не подстраивает план (дождь →
  крытые места/музеи в этот день, жара → парки/тень/вода, ясно → смотровые/закат).
- Это уже было отмечено как бэклог в `06-telegram-migration.md` («Погода в советах
  движка»).
- **Как сделать:** на клиенте уже есть прогноз по дням (wxCache). Передавать его в
  `/api/generate` (массив `{date, code, tmax}`) и добавить правило в промпт:
  «в дождливые дни ставь крытые места якорем, смотровые/пикники переноси на ясные».
  Дёшево по токенам (несколько чисел), эффект заметный.

### 3. Предупреждение об ухудшении погоды + reroute с откатом — ❌ не реализовано (на подумать)
- Сейчас нет: мониторинга изменений погоды, перестроения маршрута, истории версий
  (есть только единичный `undoSnap` для последнего действия, не версии маршрута).
- **Что нужно для фичи:**
  1. **Снимок погоды на момент генерации** — хранить в поездке прогноз, под который
     строился план (`city.wxAtGen` по дням).
  2. **Сверка при открытии** — сравнивать свежий прогноз с сохранённым; если день
     заметно «портится» (ясно → дождь), показать ненавязчивый баннер: «3 июля
     ожидается дождь — переставить план?».
  3. **Reroute** — вызвать генерацию/перестановку именно проблемного дня (можно
     переиспользовать `/api/generate-day` с пометкой «дождь, нужны крытые места»).
  4. **Версионирование с откатом** — перед reroute сохранять версию дня/поездки в
     стек версий (`city.history[]`), показывать «Вернуть прежний вариант». Это
     расширение текущего одношагового undo до полноценной истории.
- **Сложность:** средняя. П.1–2 дёшевы; п.3–4 — отдельная работа (история версий +
  UX выбора). Хороший кандидат после стабилизации базовой генерации.
- **Зависимости:** надёжный per-day reroute (есть основа — `/api/generate-day`) и
  модель версий состояния.

## Прочие идеи (из планов и ревью)

- **Google Places** — живые рейтинги/часы/фото вместо LLM-приближений (платно;
  кэшировать агрессивно — ради этого и сделан слой A).
- **Кэш-first генерация** — сперва тянуть факты мест из БД, у AI спрашивать только
  недостающее (глубже текущего «подмешивания known places»).
- **Стриминг/фоновая генерация** — чтобы длинный маршрут не рвался в мобильном
  WebView и можно было закрыть окно (Фаза 3).
- **Пуши по дедлайнам** напоминаний (бот шлёт сообщение) — Фаза 3.
- **Авто-напоминания из мест** — из `ticket.lead` считать дату «бронируй за N
  недель» и заводить напоминание автоматически.
- **Дневной лимит генераций** на пользователя — защита бюджета сверх белого списка.
- **OCR скриншотов** подборок мест на онбординге (Places autocomplete или картинки).
