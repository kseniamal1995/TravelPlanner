# Планер маршрутов — документация проекта

_Последнее обновление: версия прототипа v9 (данные `trip-planner:v2`, schema v9)_

---

## 1. О продукте

Личный планер путешествий: пользователь собирает поездку по городу, а приложение раскладывает места по дням в виде удобного **пешего маршрута от отеля**, учитывая часы работы, бронирования, нагрузку дня и предупреждения (карманники, закрытия). Цель — отдавать **готовый, «человеческий» маршрут**, который почти не нужно править вручную.

Аудитория: путешественники, которые сами планируют поездку и хотят структуру без ручного жонглирования картой.

## 2. Что уже есть (прототип)

### 2.1 Технически
- Один самодостаточный HTML/JS-файл (vanilla JS, без сборки), шрифт Nunito, светлый флоат-дизайн, акцент — сиреневый.
- Хранение: `window.storage` (в среде артефакта) с fallback в память. Ключ `trip-planner:v2`, версия схемы — 9. Непрерывная миграция по `id`: при обновлении версии данные пользователя (галочки «куплено», заметки, статус напоминаний) сохраняются.
- Полностью клиентское приложение — это будущий **фронт Telegram-аппа**.

### 2.2 Экраны
- **Главная** — список поездок, кнопка «+ Новая поездка», вход в «Напоминания» (кнопка справа сверху), описание продукта.
- **Поездка** — план по дням.
- **Идеи** — Шопинг / Еда / На потом (отдельный раздел, не дни).
- **Напоминания** — отдельный раздел с фильтром и крайними датами.

### 2.3 Функционал
- **Поездки**: несколько городов; создание поездки (город, дата старта, число дней, темп ходьбы).
- **Дни**: табы с авто-датой и днём недели (считаются из даты старта); фон таба окрашен по нагрузке дня, активный день — обводка 1px в цвет нагрузки; добавление и удаление дня (места удалённого дня уходят в «На потом»).
- **Маршрут дня**: кнопка открывает в Google Maps пеший маршрут по точкам дня (начинается с первой точки, не от отеля — чтобы не было «просто пинов»). Иконки транспорта (🚶/🚇/🚌) и время на перегонах.
- **Индикатор насыщенности дня** 🟢/🟠/🔴: считается из суммы пеших километров + числа точек + времени на осмотр, с поправкой на темп ходьбы. Есть тултип-пояснение по «?».
- **Старт от отеля**: каждый день начинается строкой «🏨 Старт» + перегон до первой точки. День прилёта — свёрнутый блок «🛬 Прибытие и заселение» (прилёт → метро до отеля → оставить сумки/заселение).
- **Точка маршрута**: название + рейтинг (в одну строку), описание, предупреждения (часы работы, безопасность), билеты (цена / «куплено» / ссылка на сайт), пометка «✅ Забронировано · дата/время» (для забронированного цена скрыта), заметка, перенос в другой день/идею, сортировка ↑↓, удаление.
- **Идеи**: Шопинг; Еда (реальные места из гайдов и конкурсов 2026 — например, лучший круассан Гран-Пари); На потом.
- **Напоминания**: отдельный раздел, фильтр «Эта поездка / Все», крайние даты с подсветкой (просрочено / скоро / ок), ссылки, добавление своих. Содержат конкретику (например, как и за сколько купить билет на метро, тип и цена).
- **Настройки поездки** (⚙): число дней, время прилёта/вылета/заселения, темп ходьбы, тип еды, отель.

### 2.4 Модель данных (упрощённо)
```
S = { version, activeCity, cities: { [id]: City } }

City = {
  id, name, tripStart, walk('low'|'med'|'high'),
  arrival, departure, checkin, food, arrivalDay,
  hotel: { name, addr, metro, gmaps }, orly,
  reminders: [ { id, text, due, url, done } ],
  days: [ { id, mode, first:{ m, t, to } } ],
  activeTab, places: [ Place ]
}

Place = {
  id, bucket (id дня | 'shop' | 'food' | 'later'),
  name, rating, pri, rname (для геокодирования),
  desc, gmaps, visit, leg:{ m, t, to },
  ticket:{ price, lead, url }, warnH, warnS,
  booked, bt (когда), rec, nort (не в маршруте),
  bought, userNote, order
}
```

### 2.5 Ключевые функции
- `routeUrl(c, dayId)` — строит ссылку Google Maps по точкам дня.
- `intensity(c, dayId)` — считает нагрузку и уровень 🟢/🟠/🔴.
- `dayLabel(start, i)` — авто-дата и день недели.
- Миграция по `id` при росте версии схемы.

## 3. Что нужно сделать для Telegram-аппа

### 3.1 Инфраструктура
- **Бот** через BotFather; регистрация Mini App с URL приложения.
- **Хостинг** фронта (Vercel / Netlify).
- Подключить **`telegram-web-app.js`**: тема Telegram, `initData` (идентификация пользователя), MainButton/BackButton, haptics.
- **Хранение на пользователя**:
  - MVP — Telegram **CloudStorage** (key-value, без своей БД).
  - Масштаб — БД (рассматривали **Vercel Postgres**), ключ = Telegram user id.
  - Технически: заменить прямые вызовы `window.storage` на **адаптер хранилища** (один интерфейс get/set, реализации: artifact / CloudStorage / API).

### 3.2 Бэкенд
- API на serverless (Vercel functions / Node).
- **Валидация `initData`** (проверка подписи Telegram) — обязательна для безопасности.
- **Генерация маршрута**: вызов **LLM (Claude API)** по входным данным пользователя + **Places API** (Google Places) для рейтингов, координат, часов работы, фото и ссылок; геокодирование вместо ручных ссылок.

### 3.3 Онбординг любого пользователя
- Шаги: город → даты → где живёшь (отель/район) → темп ходьбы → интересы (арт/еда/шопинг/виды/ночная жизнь) → must-see → фиксированные события (концерт, бронь).
- **Ввод мест**:
  - поиск места внутри аппа (Places autocomplete);
  - или OCR скриншотов (загрузка картинок → распознавание названий).
  - ⚠️ Прямой импорт Google-подборки невозможен — официального API нет.

### 3.4 Умный движок маршрута (правила, которые надо зашить)
Это то, из-за чего сейчас маршрут приходится править руками. Движок должен «думать как человек»:
- **Кластеризация** точек по районам — один день = одна пешеходная зона.
- **Якорь дня**: главное по таймслоту/билету (музей, концерт), остальное лёгкое вокруг; два тяжёлых музея подряд — нет.
- **Часы и день недели**: авто-учёт закрытий (музеи пн/вт), воскресных закрытий магазинов, последнего входа; таймслоты — в их окна.
- **Кривая усталости / лимит точек** под выбранный темп.
- **Старт у метро, финиш у метро**; подсказка, где выходить.
- **Тайминг впечатлений**: рынки утром, закат/подсветка вечером, обед по пути.
- **Маленькие радости**: утренний кофе/круассан, перерыв в саду.
- **Дефолты почти без правок**: сам выбирает must-see и порядок; пользователь подталкивает («чиллее», «добавь еду»), а не пересобирает.

### 3.5 Дополнительный функционал
- **Пуш-уведомления** по крайним датам напоминаний (бот шлёт сообщение, когда подходит дедлайн брони).
- **Авто-подбор еды** под тип (перекус/ресторан) и бюджет — из гайдов/конкурсов и по рейтингу Places.
- **Бронь-лиды**: что и за сколько бронировать (Эйфелева 4–6 недель, Нотр-Дам за 2–3 дня и т.д.).
- **Шаринг** маршрута (deeplink), совместная поездка.

## 4. Переход от прототипа к продукту
- Текущий фронт — переиспользуемый UI-прототип.
- Шаги миграции:
  1. Вынести хранилище в **адаптер** (artifact → CloudStorage → API).
  2. Подключить **Telegram SDK** (identity, theme, кнопки).
  3. Перенести генерацию плана (сейчас зашитый seed) на **бэкенд** (LLM + Places).
  4. Заменить ручное геокодирование на **Places API**.

## 6. Открытые вопросы и риски
- **Импорт Google-подборки невозможен** — нужен поиск в аппе или OCR скринов.
- **Стоимость API** (LLM-генерация + Places-запросы) — заложить лимиты/кэш.
- **Качество маршрутов** — нужны правила (раздел 3.4) и проверочные сценарии (эвалы).
- **Приватность** — данные пользователей и валидация `initData`.
